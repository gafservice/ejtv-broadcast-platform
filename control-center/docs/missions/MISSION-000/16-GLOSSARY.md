# Introducción

A lo largo del desarrollo del EJTV Broadcast Platform se utilizan
conceptos propios de la ingeniería de software, la administración de
infraestructura y la arquitectura de sistemas.

El propósito de este glosario consiste en establecer un vocabulario
común para todos los integrantes del proyecto.

Las definiciones aquí presentadas representan el significado oficial de
cada término dentro de la documentación del proyecto.

---

# Adaptador (Adapter)

Componente encargado de comunicar el dominio del proyecto con una
tecnología específica.

Su función consiste en aislar la infraestructura del resto del sistema,
permitiendo que las reglas del negocio permanezcan independientes de la
implementación tecnológica.

---

# API

Interfaz mediante la cual clientes y aplicaciones externas interactúan
con el EJTV Control Center.

La API recibe solicitudes, coordina la ejecución de los servicios y
devuelve respuestas estructuradas.

---

# Arquitectura

Conjunto de decisiones fundamentales que definen la organización del
proyecto.

La arquitectura establece las responsabilidades de cada capa y regula
las dependencias entre los diferentes componentes del sistema.

---

# Baseline

Registro oficial del estado alcanzado por el proyecto al finalizar una
misión.

El Baseline constituye el punto de referencia desde el cual continuará
la evolución del sistema.

---

# Capacidad (Capability)

Funcionalidad incorporada al proyecto para resolver una necesidad
específica.

Cada capacidad se desarrolla mediante una misión y debe cumplir el
proceso oficial de diseño, implementación, validación y documentación.

---

# CHANGELOG

Documento que registra cronológicamente los cambios relevantes
incorporados durante una misión.

Su propósito consiste en conservar la evolución técnica del proyecto.

---

# Dominio (Domain)

Núcleo conceptual del proyecto.

Representa las reglas del negocio y los modelos que describen el
problema que la plataforma busca resolver.

El dominio no depende de tecnologías específicas.

---

# Evidencia

Información que demuestra la ejecución de una actividad y respalda los
resultados obtenidos durante el desarrollo.

Las evidencias pueden estar representadas por reportes, registros,
capturas de pantalla o resultados de pruebas.

---

# Ingeniería

Disciplina encargada de planificar, diseñar, implementar, validar y
documentar soluciones técnicas siguiendo un proceso estructurado.

En este proyecto, la ingeniería constituye el fundamento sobre el cual
se desarrolla el software.

---

# Manual de Ingeniería

Conjunto de documentos que establecen las normas oficiales utilizadas
durante el desarrollo del proyecto.

Incluye estándares relacionados con documentación, arquitectura,
programación, pruebas y control de versiones.

---

# Misión (Mission)

Unidad principal de desarrollo del proyecto.

Cada misión incorpora una o varias capacidades y produce un conjunto
completo de documentación, pruebas, evidencias y un Baseline.

---

# Proyecto

Conjunto organizado de componentes, procesos, documentos y capacidades
que conforman el EJTV Broadcast Platform.

El proyecto evoluciona mediante la incorporación progresiva de nuevas
misiones.

---

# Prueba (Test)

Procedimiento utilizado para verificar el correcto funcionamiento de un
componente o capacidad.

Las pruebas permiten validar objetivamente el estado del proyecto antes
de integrar nuevos desarrollos.

---

# Repositorio

Espacio donde se almacena el código fuente, la documentación y los
demás recursos que forman parte del proyecto.

El repositorio constituye la fuente oficial del desarrollo del
EJTV Broadcast Platform.

---

# Roadmap

Documento que describe la planificación estratégica del proyecto.

Presenta la secuencia prevista para incorporar nuevas capacidades y
orienta la evolución general de la plataforma.

---

# Servicio (Service)

Componente responsable de coordinar la lógica de aplicación.

Los servicios organizan el flujo de trabajo entre la API, el dominio y
los adaptadores, manteniendo separadas las responsabilidades de cada
capa.

---

# Sprint

Conjunto de actividades planificadas para desarrollar una parte de una
misión.

Cada sprint produce un resultado verificable que contribuye al avance
general del proyecto.

---

# Trazabilidad

Capacidad de reconstruir la historia de una decisión, una modificación o
una capacidad mediante la documentación, las evidencias y el historial
del proyecto.

La trazabilidad constituye uno de los principios fundamentales del
EJTV Broadcast Platform.

---

# Validación

Proceso mediante el cual se comprueba que una capacidad cumple los
requisitos funcionales, arquitectónicos y de calidad establecidos por el
proyecto.

La validación incluye pruebas, revisión de resultados y generación de
evidencias.

---

# Versión

Identificador utilizado para distinguir diferentes estados de un mismo
componente o documento.

El control de versiones permite conocer la evolución histórica del
proyecto.

---

# Resultado

Con este documento se completa el vocabulario oficial utilizado durante
la MISSION-000.

Las definiciones aquí presentadas servirán como referencia para todas
las misiones y documentos desarrollados en el futuro.

---

# Relación con el proyecto

El presente glosario constituye una referencia permanente para la
documentación del EJTV Broadcast Platform.

Su actualización acompañará la evolución del proyecto y permitirá
mantener un lenguaje técnico uniforme entre todos los integrantes del
equipo.

---

# Cierre de la MISSION-000

Con la finalización de este documento concluye oficialmente la
MISSION-000 — Engineering Foundation.

A partir de este momento el proyecto dispone de:

- un modelo de gobierno;
- una arquitectura documentada;
- un Manual de Ingeniería;
- una metodología de desarrollo;
- una estructura documental;
- una estrategia de pruebas;
- un sistema de evidencias;
- un proceso de generación de Baselines;
- un vocabulario técnico común.

Estos elementos constituyen la base sobre la cual continuará
evolucionando el EJTV Broadcast Platform durante las siguientes
misiones.
